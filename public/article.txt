Here's what I found on increasing num_ctx in an Ollama Modelfile and its VRAM impact:
To increase the context window in Ollama, you add PARAMETER num_ctx <tokens> inside a Modelfile, then create a new model variant using ollama create.
1. Step-by-Step Guide & Modelfile Syntax
Export the current Modelfile configuration (optional):
ollama show llama3.2 --modelfile > Modelfile
Edit the Modelfile: Define the base model using FROM and set your context window size with PARAMETER num_ctx:
FROM llama3.2
PARAMETER num_ctx 8192
(Common values: 8192 for 8k, 16384 for 16k, 32768 for 32k tokens).
Build the new model:
ollama create llama3.2-8k -f Modelfile
Run the customized model:
ollama run llama3.2-8k
(Note: Context size can also be set temporarily during CLI sessions via /set parameter num_ctx 8192 or when starting the service via OLLAMA_CONTEXT_LENGTH=64000 ollama serve).
2. Modelfile Reference Overview
According to Ollama Documentation, valid instructions in a Modelfile include:
FROM (Required): Defines the base model or path.
PARAMETER: Configures model execution parameters (num_ctx, temperature, top_p, top_k, stop, etc.).
SYSTEM: Specifies a custom system prompt.
TEMPLATE: Configures the prompt template structure sent to the LLM.
MESSAGE: Pre-populates conversation turn history.
ADAPTER: Specifies LoRA adapters to apply.
LICENSE: Sets legal licensing parameters.
3. Impact on VRAM & Hardware Requirements
KV Cache Allocation: Expanding num_ctx increases the memory required for the model's Key-Value (KV) cache. Ollama pre-allocates VRAM for this full context window when loading the model.
VRAM Overhead Examples:
2,048 tokens: ~16.1 GB total VRAM
8,192 tokens: ~16.5 GB total VRAM
32,768 tokens: ~17.9 GB total VRAM
131,072 tokens: ~23.5 GB total VRAM
CPU Offloading & Latency: If available GPU VRAM is insufficient to hold the model weights plus the expanded KV cache, Ollama offloads layers to system RAM. This prevents out-of-memory crashes, but significantly reduces inference speed.

Key themes across web documentation:
Modelfile compilation: Updating default parameters permanently requires saving a Modelfile and compiling it with ollama create.
Dynamic VRAM consumption: The KV cache footprint scales linearly with context length.
Hardware-based defaults: Ollama automatically sets default context sizes based on GPU VRAM (<24 GB VRAM defaults to 4k, 24–48 GB defaults to 32k, >=48 GB defaults to 256k).

The Context Window and Silent Amnesia
Context length is the maximum number of tokens a model can keep in memory while generating a response. It determines how much previous conversation, source code, or document content the model can evaluate.
By default, Ollama often restricts context windows to 2048 or 4096 tokens to protect system resources. If your VRAM is under 24 GiB, Ollama defaults to a 4k context window; if you have 24-48 GiB, it scales up to 32k.
For advanced tasks like agent execution, coding tools, and deep web searches, you typically need a context window of at least 64,000 tokens. When a model's default limit is too low, it quietly pushes out the oldest data in the chat. This means your model might forget its original role-playing guidelines or critical code files you pasted just minutes prior.
Checking Model Limits and Hardware Allocations
Before altering any parameters, you need to know what your system is running. Ollama splits context information into two distinct categories:
Model's Maximum Context Length: The physical ceiling determined by the model's architecture. To see this, use: ollama show <model_name> Inside the output, look for the context length row (for example, 40960 tokens).
Current Session Context Length: The actual memory actively allocated to a running session. You can inspect this by running: ollama ps Note that this command only returns active statistics when a model is currently loaded in memory.
Under the PROCESSOR column of ollama ps, you will see a percentage breakdown (such as 100% GPU or a split like 48%/52% CPU/GPU). For the best speed and lowest latency, you want to keep your model completely on your GPU's fast VRAM. Offloading any layers to system RAM and the CPU slows processing down significantly.
Creating Custom Models with Modelfiles
If you try to dynamically adjust parameters during an interactive CLI session using commands like /set parameter num_ctx 8192, your changes will disappear as soon as the model is unloaded from memory. To make these changes permanent, you can design a Modelfile—which acts as a configuration blueprint to compile a custom model.
Creating a custom model is straightforward:
Create a blueprint file (e.g., Modelfile.custom):
# Specify the base model
FROM llama3.2

# Set the new persistent context window size
PARAMETER num_ctx 8192

# Assign a behavior or role
SYSTEM "You are a precise JSON formatting assistant."
Compile the model in your terminal using ollama create: ollama create llama3.2-8k -f Modelfile.custom
Ollama compiles this instantly. It doesn't redownload gigabytes of model weights; it simply applies your settings as a lightweight layer on top of your existing base model.

Balancing Context Size with Hardware Memory
Increasing your model's context window requires more system memory. This is because Ollama stores conversational token data in a structure called the KV Cache. As your context gets longer, the KV cache grows non-linearly due to attention mechanisms, which can easily trigger memory freezes.
Use this rough memory safety guide based on your computer's RAM:
8 GB RAM: Maximum context of 4096 tokens.
16 GB RAM: Comfortably handles up to 8192 tokens.
32 GB+ RAM: Can safely attempt 16384 tokens or higher.
If you want to run massive context windows without buying new hardware, you can turn on KV Cache Quantization. Running your server with this environment variable: OLLAMA_KV_CACHE_TYPE=q4_0 ollama serve
This compresses the KV cache to 4-bit precision, cutting its VRAM footprint down to roughly 1/4 of its normal size, allowing you to run much wider context windows with minimal speed losses.
Dynamic Context Overrides
While Modelfiles are the gold standard for creating persistent models, you can also alter context sizes temporarily or programmatically without making a new model.
Through the CLI (Interactive Session): Launch your model, type /set parameter num_ctx 8192 to alter the context size, and optionally run /save <new_model_name> to permanently save your changes to a new model profile.
Through Environment Variables: Launch your Ollama server with a global override: OLLAMA_CONTEXT_LENGTH=8192 ollama serve
Through the REST API: Pass the num_ctx value inside the options block of your JSON payload:
{
  "model": "llama3.2",
  "prompt": "Analyze this code...",
  "options": {
    "num_ctx": 8192
  }
}
