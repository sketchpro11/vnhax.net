Core Subsystems Breakdown

Ollama's codebase is designed with strict boundaries separating client entrypoints, runner scheduling, and device discovery. Here is how each subsystem operates in production:

01 • Engine

Inference Service

Receives incoming REST requests, schedules prompt execution, inspects GPU/CPU device availability, and executes models through llama.cpp or Apple Silicon MLX.

  • routes.go HTTP API
  • sched.go Scheduler
  • llama_server.go llama.cpp Runner
  • runner.go Apple MLX
02 • Storage

Model Management

Handles cryptographic layer verification, model manifests, chunked GGUF blob storage, and the safetensors-to-GGUF conversion pipeline.

  • model_resolver.go Resolver
  • manifest.go Manifest Store
  • download.go Pull / Push
  • pipeline.go Safetensors
03 • Clients

User Clients

Cross-platform interactive entrypoints including the primary CLI terminal wrapper, packaged desktop tray app, React web chat, and local SQLite/JSON chat persistence.

  • cmd.go Ollama CLI
  • app.go Desktop App
  • main.tsx Web Chat UI
  • database.go Chat Store
04 • Agents

Agent Integrations

Middleware proxies that adapt standard OpenAI and Anthropic API protocols so local Ollama instances can act as drop-in backends for Claude Desktop and agent frameworks.

  • launch.go Agent Launch
  • claude_desktop.go Desktop Proxy
  • anthropic.go Anthropic Adapter

Quick Start & Usage Examples

Once Ollama is running on port 11434, you can interact with local weights using the CLI or standard HTTP requests:

TERMINAL CLI 
# Download and run Llama 3.3 locally
ollama run llama3.3

# Run reasoning models
ollama run deepseek-r1:8b
REST API (CURL) 
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.3",
  "prompt": "Why is the sky blue?",
  "stream": false
}'
